# Publishing to the DITA-OT Plugin Registry

How `io.github.jyjeanne.dita2epub` is published to the [DITA-OT plugin registry](https://www.dita-ot.org/plugins),
following [Publishing plug-ins to the registry](https://www.dita-ot.org/dev/topics/plugins-registry.html#plugin-registry__publishing-to-registry)
and the [registry repository](https://github.com/dita-ot/registry).

## How the Registry Works

The registry is the [dita-ot/registry](https://github.com/dita-ot/registry) Git repository. It holds one JSON file per
plugin, named after the plugin ID (`io.github.jyjeanne.dita2epub.json`), with an array of entries, one per version.

`dita install io.github.jyjeanne.dita2epub` (or `...@2.1.0` for a given version) reads the entries, keeps the versions
whose dependencies the installed DITA-OT satisfies, downloads the ZIP from `url`, checks it against `cksum`, and
installs it.

| Key | Required | Value for this plugin |
|-----|----------|-----------------------|
| `name` | Yes | `io.github.jyjeanne.dita2epub`, the `id` of `plugin.xml` |
| `vers` | Yes | The plugin version (`x.y.z`), as in `plugin.xml` |
| `deps` | Yes | `org.dita.base` (mandatory, defines the supported DITA-OT versions) and `org.dita.html5`, both `>=4.4.0` |
| `url` | Yes | The ZIP attached to the GitHub release: `https://github.com/jyjeanne/dita2epub/releases/download/v<version>/io.github.jyjeanne.dita2epub-<version>.zip` |
| `cksum` | No | SHA-256 of that exact ZIP |
| `description`, `keywords`, `homepage` | No | Shown on [dita-ot.org/plugins](https://www.dita-ot.org/plugins) |
| `license` | No | `Apache-2.0` (SPDX identifier) |

Registry rules: one pull request per plugin version; commits signed off (`git commit -s`, the
[Developer Certificate of Origin](https://www.dita-ot.org/DCO)); a new version is added to the array, existing
entries are never overwritten, so that older DITA-OT installations can still install older versions.

## Prerequisites

- **A public download URL.** `dita install` downloads the ZIP without authentication. Assets of a private GitHub
  repository cannot be downloaded that way, so the repository must be public (or the ZIP published elsewhere)
  before the entry is submitted.
- **GitHub Actions enabled** for the repository, with permission to create releases: the release is built by the
  [Release workflow](../.github/workflows/release.yml).
- **An entry for the version** in [`io.github.jyjeanne.dita2epub.json`](../io.github.jyjeanne.dita2epub.json), with
  `vers` and `url` but no `cksum`: the release workflow fails when the entry is missing. Do not write an empty
  `cksum`: DITA-OT then rejects every download ("checksum ... does not match expected value").

## Step 1: Prepare the Release

1. Set the version in `build.gradle.kts`; `plugin.xml` and `plugin-info.xml` must declare the same one
   (`./gradlew verifyPluginVersion`).
2. Add the `## [x.y.z]` section to [CHANGELOG.md](CHANGELOG.md): the release workflow uses it as release notes.
3. Add the entry of the version to `io.github.jyjeanne.dita2epub.json`.
4. Merge into `main`.

## Step 2: Tag the Release

```bash
git tag -a v2.1.0 -m "Release v2.1.0"
git push origin v2.1.0
```

The Release workflow then:

1. builds and tests the plugin, checks that `io.github.jyjeanne.dita2epub.json` has an entry for the version, installs
   the distribution ZIP into DITA-OT 4.4.1 and builds the sample bookmap with it;
2. creates the GitHub release `v2.1.0` with three assets: the distribution ZIP, its `.SHA-256` file, and
   `io.github.jyjeanne.dita2epub.json`, the registry entry of the version with the `url` and `cksum` of the attached
   ZIP (generated by [`.github/scripts/registry-entry.js`](../.github/scripts/registry-entry.js));
3. shows that entry in the run summary.

The checksum must come from the released ZIP. A ZIP built locally differs (on Windows, for example, text files are
checked out with CRLF line endings, on the Linux runner with LF), and DITA-OT refuses a ZIP whose checksum does not
match.

## Step 3: Record the Checksum

Copy the `cksum` of the generated entry into this repository's `io.github.jyjeanne.dita2epub.json` and commit it, so
that the file stays the complete history of the published versions.

## Step 4: Test the Entry with a Custom Registry

Before submitting, check the entry the way users will install the plugin:

1. Fork [dita-ot/registry](https://github.com/dita-ot/registry) and create a branch, for example `add-dita2epub-2.1.0`.
2. In that branch, add the entry to `io.github.jyjeanne.dita2epub.json` (create the file for the first version,
   otherwise add the entry to its array).
3. In a test DITA-OT installation, edit `config/configuration.properties` so that the branch is searched first:
   ```properties
   registry = https://raw.githubusercontent.com/<your-user>/registry/add-dita2epub-2.1.0/ https://plugins.dita-ot.org/
   ```
4. Install by name and check:
   ```bash
   dita install io.github.jyjeanne.dita2epub
   dita plugins                # lists io.github.jyjeanne.dita2epub@2.1.0
   dita --input=mybook.ditamap --format=epub3 --output=out
   ```

## Step 5: Submit the Pull Request

```bash
cd <registry-fork>
git add io.github.jyjeanne.dita2epub.json
git commit -s -m "Add io.github.jyjeanne.dita2epub 2.1.0"
git push origin add-dita2epub-2.1.0
```

Open a pull request against `master` of `dita-ot/registry`, for this version only. Once it is merged, the plugin
appears on [dita-ot.org/plugins](https://www.dita-ot.org/plugins) and installs with:

```bash
dita install io.github.jyjeanne.dita2epub
```

## Later Versions

Repeat the steps for each release: add the new entry to `io.github.jyjeanne.dita2epub.json` here, then to the array of
the same file in the registry, in a pull request of its own.

## Troubleshooting

| Message | Cause |
|---------|-------|
| `Downloaded plugin file checksum ... does not match expected value` | `cksum` is empty or is not the checksum of the ZIP at `url` |
| `invalid URI scheme file` | The registry location and `url` must be HTTP(S) URLs; to test locally, serve the files with a local web server |
| `The input line is too long` (Windows) | `dita.bat` builds a class path longer than the `cmd.exe` limit when DITA-OT sits in a deep folder; use a short path such as `C:\dita-ot` |

The 2.1.0 entry was tested on 2026-10-27 with a local registry and a clean DITA-OT 4.4.1: installation by name, the
plugin listed as `io.github.jyjeanne.dita2epub@2.1.0`, and a sample EPUB that passes EPUBCheck; an empty or wrong
`cksum` was rejected.
